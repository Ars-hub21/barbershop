# Настройка приёма фото галереи на стороне Google (лист "Галерея")

Этот файл — инструкция для того, кто обслуживает Google Apps Script проекта
(тот же скрипт, что стоит за `CONFIG.API_URL` в `js/core/config.js`). Она
описывает, что нужно добавить **на стороне Google**, чтобы новая вкладка
"Галерея" на странице Истории панели барберов (`barber_panel/history.html`)
могла сохранять загруженные фото.

**Важно:** фронтенд (файлы `barber_panel/gallery-tool/gallery-tool.js` и
`gallery-tool.css`) уже полностью готов и ничего в основной логике/API
проекта не менял. Пока шаги ниже не выполнены на стороне Google, форма в
панели будет кадрировать и конвертировать фото в WebP как положено, но при
отправке будет показывать ошибку — это ожидаемо, ошибка так и объясняет
пользователю, что нужно настроить приём на сервере.

---

## 1. Что именно отправляет фронтенд

Когда барбер в панели загружает фото, браузер сам конвертирует его в WebP
и обрезает под формат карточки галереи сайта (4:3, 900×675px), а затем
отправляет на `CONFIG.API_URL` (тот же URL, что используется для всех
остальных действий проекта) POST-запрос с телом:

```json
{
  "action": "addGalleryPhoto",
  "gender": "masculine",
  "title": "Классическая стрижка",
  "type": "before",
  "imageMime": "image/webp",
  "imageBase64": "<строка base64, БЕЗ префикса data:image/webp;base64,>",
  "capturedAt": "2026-09-02T10:15:00.000Z"
}
```

Пояснения по полям:
- `gender` — `"masculine"` или `"feminine"` (какая версия сайта — мужская/женская);
- `title` — название работы/категории, как его ввёл барбер (например,
  "Классическая стрижка", "Маникюр и дизайн ногтей" — обычно совпадает с
  одной из категорий в `js/data/gallery.js`, но это просто текст, не строгий enum);
- `type` — `"before"` или `"after"` (фото "до" или "после");
- `imageBase64` — уже готовое WebP-изображение в base64 (без data-URL префикса,
  его нужно будет добавить обратно при необходимости: `data:image/webp;base64,` + строка);
- `capturedAt` — ISO-дата момента кадрирования на клиенте (для сортировки/лога).

Размер `imageBase64` **специально ограничен на фронтенде примерно 45 000
символов** (см. `MAX_BASE64_LENGTH` в `gallery-tool.js`) — с запасом внутри
лимита ячейки Google Таблицы в ~50 000 символов. Если решите хранить фото
не в самой таблице (вариант Б ниже), это ограничение можно будет снять на
фронтенде отдельным изменением, но пока оно есть и трогать его не нужно.

---

## 2. Создать лист "Галерея"

В той же Google Таблице, где уже есть листы вроде "Заказы"/"Отзывы"/"История",
добавьте новый лист с точным названием **`Галерея`** и заголовками в первой строке:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Дата | Пол | Название | Тип | Фото | Статус |

Где `Фото` — либо сама base64-строка (вариант А), либо ссылка на файл в
Google Drive (вариант Б, рекомендуется — см. ниже). `Статус` можно
использовать вручную (например, "новое" / "добавлено на сайт"), чтобы
администратор видел, какие фото уже перенёс в `js/data/gallery.js`, а
какие ещё нет — сам перенос на сайт по-прежнему делается вручную, как и
раньше с мастерами и остальными данными проекта.

## 3. Добавить обработку action = "addGalleryPhoto" в doPost

В существующем `doPost(e)` (или как называется точка входа в вашем Apps
Script проекте) есть диспетчер по `action` — то же самое место, где
обрабатываются `getReviews`, `addHistory`, `updateOrderStatus` и т.д.
Нужно добавить туда ветку для `addGalleryPhoto`. Ниже — два готовых
варианта реализации самой функции, добавьте один из них и вызов из
диспетчера.

### Вызов из диспетчера (добавить рядом с остальными action)

```javascript
} else if (action === 'addGalleryPhoto') {
  result = addGalleryPhoto(data);
}
```

### Вариант А — хранить фото прямо в ячейке листа (проще, но есть лимит)

Самый быстрый способ, ничего дополнительно настраивать не нужно. Ограничение:
ячейка Google Таблицы вмещает около 50 000 символов — фронтенд уже держит
base64 в пределах ~45 000, так что укладывается, но при желании прикрутить
более крупные/качественные фото в будущем этот вариант не подойдёт.

```javascript
function addGalleryPhoto(data) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Галерея');
  if (!sheet) {
    throw new Error('Лист "Галерея" не найден — создайте его согласно GALLERY-SHEET-SETUP.md');
  }
  var dataUrl = 'data:' + (data.imageMime || 'image/webp') + ';base64,' + data.imageBase64;
  sheet.appendRow([
    data.capturedAt || new Date().toISOString(),
    data.gender || '',
    data.title || '',
    data.type || '',
    dataUrl,
    'новое'
  ]);
  return { success: true };
}
```

### Вариант Б — сохранять файл в Google Drive, в таблицу писать только ссылку (рекомендуется)

Более надёжный и гибкий вариант: изображение сохраняется как отдельный файл
в папке на Google Drive, а в таблицу записывается только прямая ссылка на
него. Так лист остаётся лёгким, а ограничение в ~50 000 символов на ячейку
перестаёт быть проблемой даже при более качественных фото в будущем.

```javascript
function addGalleryPhoto(data) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Галерея');
  if (!sheet) {
    throw new Error('Лист "Галерея" не найден — создайте его согласно GALLERY-SHEET-SETUP.md');
  }

  // Замените на ID нужной папки на Google Drive (создайте папку "Галерея сайта"
  // и возьмите её ID из адресной строки — часть после /folders/ в URL папки).
  var FOLDER_ID = 'ВСТАВЬТЕ_СЮДА_ID_ПАПКИ_НА_DRIVE';
  var folder = DriveApp.getFolderById(FOLDER_ID);

  var mime = data.imageMime || 'image/webp';
  var bytes = Utilities.base64Decode(data.imageBase64);
  var blob = Utilities.newBlob(bytes, mime, (data.title || 'photo') + '-' + (data.type || '') + '-' + Date.now() + '.webp');
  var file = folder.createFile(blob);

  // Открываем доступ на чтение по ссылке, чтобы фото можно было потом
  // подставить в src на сайте (после того как администратор перенесёт его
  // в js/data/gallery.js — этот шаг всё ещё выполняется вручную).
  file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);

  var directUrl = 'https://drive.google.com/uc?export=view&id=' + file.getId();

  sheet.appendRow([
    data.capturedAt || new Date().toISOString(),
    data.gender || '',
    data.title || '',
    data.type || '',
    directUrl,
    'новое'
  ]);

  return { success: true, url: directUrl };
}
```

Если проект уже использует `DriveApp` где-то ещё (например, для фото
мастеров) — используйте тот же подход/папку, что и там, для единообразия.

---

## 4. После настройки

Как только один из вариантов выше добавлен в Apps Script и **опубликован
как новое развёртывание** (Deploy → Manage deployments → New version —
без этого шага изменения в коде не подхватятся по существующему URL),
форма в панели барберов начнёт реально сохранять фото на лист "Галерея"
без каких-либо изменений на фронтенде — он уже отправляет данные в нужном
формате.

Финальный шаг переноса фото с листа "Галерея" на сам сайт (в
`js/data/gallery.js`) по-прежнему делается вручную администратором — так
же, как сейчас вручную обновляются мастера и другие данные проекта. Это
осознанное решение: сайт не должен публиковать фото автоматически, без
проверки.
